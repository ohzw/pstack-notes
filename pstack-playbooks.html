1 ANATOMY1 本の形
① 責任の宣言太字の 1 行目
何に責任を持つか。持たない物も書く。
You own this task. Plan, review, verify. （bug-fix）You own the program, never the code. （orchestrate）
② 手順番号付きリスト
ほとんどが「どのスキル・原則をいつ呼ぶか」と「通らないと次へ進めない関門」。
Reproduce it yourself on the matching surface … Binary-search the cause … If it crosses a function boundary, architect first. （bug-fix 1〜3）
③ 抜け道を塞ぐ一文手順の中や前置き
楽な判定を名指しで禁じる。
"Inconclusive" or wrong-surface is not a pass. （判定できなかった・別の画面で試した、は合格ではない）Belt-and-suspenders that "might help" is a hypothesis, not a fix. （念のための変更は仮説の扱い）
④ 次へ渡す先最後の手順
終わったらどのプレイブックに移るか。
Run Opening a PR. （作る系はすべて）Hand back to Bug fix or Perf once the cause is known. （runtime-forensics）
⑤ Reply末尾の太字
最後の報告に入れる物。そのプレイブックに固有の項目だけを書く。
what was broken, root cause, fix, how you verified. Paste failing-then-passing repro output verbatim. （bug-fix）

ルーターでの使われ方

/poteto-mode は依頼に合うプレイブックを 1 本選び、その手順を todo の先頭に一字一句そのまま写す。やらない手順も消さず、skip: 理由 を付けて残す。作業固有の todo はその後ろに足す。

  • Reproduce it yourself on the matching surface …
  • Binary-search the cause …
  • Plan the fix …
  • Verify on the same surface …
  • Stage the commits … — skip: 安いテストの道が無い
  • Run Opening a PR.
  • （ここから作業固有の todo）

合うプレイブックが無い時や、大きく範囲が広い時は figure-it-out が専用の手順を設計する。数日規模の計画は orchestrate に回す。

4 ESSENCE7 つの考え方解釈

01まず「誰の物か」を決める

1 行目で責任の範囲を決める。大事なのは持たない物の宣言で、エージェントが仕事の範囲を勝手に広げるのを止めている。

持たない物を書いている例
orchestratemulti-phase-planautopilot-fullautopilot-stackprototypevisual-parityrefactoring

02本物で確かめる関門を作業ごとに決める

何を本物とするかは作業で違う。「判定できなかった」「別の画面」「コンパイルが通った」「CI が緑」は、どれも合格にならない。

バグ同じ画面での再現
速さ計測した数字
見た目画像の差分
eval会話記録（自己申告ではない）
マージ書いた本人以外の判定と patch-id
引き継ぎ前の担当の「通った」を本物で確かめ直す

031 つ変えたら 1 回確かめ、効かなければ戻す

「念のため」の変更は仮説の扱い。証拠が無ければ残さない。確かめる前に次の変更を重ねない。

例
bug-fixperf-issuehillclimbrefactoringautonomous-run

04作った人と判定する人を分ける

作った本人は「作るつもりだった物」を確かめてしまう。判定は書いていない役、できれば別系統のモデルが出す。

例
shippingautopilot-fullautopilot-stackevalmulti-phase-plan

05書き手は 1 人

PR の積み方を変えるのは 1 人、PR ごとに担当 1 人、見張りは積み重ね 1 つに 1 人、記録ファイルも 1 つに 1 人。同時に動く役が増えるほど、この決まりが細かくなる。

例
autopilot-stackautopilot-fullbabysitorchestratevisual-parity

06人に聞くのは取り消せない操作と好みだけ

動かせば分かることは prototype で確かめて決める。再現も自分でやる。orchestrate には「人間に上げない物」の一覧まである。

例
prototypebug-fixautonomous-runorchestrateworktree-cleanup

07終わり方を先に決める

Reply 欄で報告の中身が決まっている。どこで止まるかも先に書く。investigation は PR を作らない。forensics は直さない。pause は最終報告ではない。

例
investigationruntime-forensicstrace-forensicspause-safelyautonomous-runhillclimbbabysitshipping
